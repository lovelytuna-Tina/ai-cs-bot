# AI 智能客服助手

> 基于 RAG + Function Calling + 多轮记忆 + 人工转接的企业级全流程电商客服系统

一个具备知识库检索、工具自主调用、上下文记忆和情绪感知转接的智能客服解决方案。覆盖售前咨询、售中下单、售后维权的完整业务闭环，开箱即用。

## 项目亮点

- **RAG 知识库**：87 条 FAQ 向量化检索，回答退换货政策、保修条款等标准问题，不依赖 LLM 预训练知识
- **Function Calling**：10 个业务工具，LLM 自主决策调用哪个工具，实现"查订单、查物流、下单、退款"等真实操作
- **多轮对话记忆**：按会话 ID 保持上下文，支持连续追问（"上面那个订单的物流呢？"），最多保留 10 轮
- **人工转接引擎**：六维检测（关键词 / 负面情绪 / 感叹号密度 / 对话轮次 / 重复提问 / 连续疑问），自动判断何时转人工
- **多模态视觉分析**：集成 qwen-vl-plus 视觉大模型，用户上传商品照片即可自动识别破损、错发、漏发等问题，分析结果注入对话上下文
- **全流程覆盖**：售前（商品搜索、详情、库存）→ 售中（下单、支付、改地址）→ 售后（查单、查物流、工单、退款）
- **企业级前端**：清新淡雅的浅绿色设计，支持客服调试模式、响应式布局、无障碍访问（A11y 评分 96/100）

### 请求处理流程

每条用户消息经过四个阶段：

**阶段一：人工转接检测** (`handoff.py`)

六个条件满足任一即触发转接：
- 用户明确要求（"转人工"、"找客服"等）
- 负面情绪词命中（"骗子"、"垃圾"、"投诉"等 22 个关键词）
- 感叹号密度 >= 3，判断为情绪激动
- 对话超过 4 轮（8 条消息），疑似问题未解决
- 重复提问检测（与历史消息 Jaccard 相似度 > 0.5）
- 连续疑问检测（连续 2 条消息含多个问号）

**阶段二：RAG 知识库检索 + 视觉分析** (`rag.py` + `llm.py`)

将用户消息与 87 条 FAQ 做语义相似度匹配，取 Top-K 相关条目作为上下文。这让客服能准确回答"退换货政策是什么"、"保修期多久"等标准问题。

若用户上传了商品图片，调用 qwen-vl-plus 视觉大模型识别破损、错发、漏发等问题，分析结果作为上下文注入后续回复。

**阶段三：Function Calling 工具调用** (`agent.py`)

LLM 根据用户意图自主决策调用哪个工具。例如用户问"订单 20250812001 到哪了"，LLM 会：
1. 判断需要调用 `query_logistics` 工具
2. 提取参数 `order_id="20250812001"`
3. 执行工具，拿到物流数据
4. 将物流数据组织成自然语言回复

function calling 失败时（超时、限流），自动降级为规则引擎匹配，保证工具调用不中断。

**阶段四：LLM 回复生成** (`llm.py`)

将系统提示 + 对话历史 + RAG 检索结果 + 工具返回数据组合后，调用通义千问生成最终回复。LLM 客户端设置 30 秒超时，失败时返回友好提示而非崩溃。

## 快速开始

### 环境要求

- Python 3.10+
- 阿里云 DashScope API Key（免费申请：https://dashscope.console.aliyun.com/）

### 安装步骤

```bash
# 1. 克隆项目
git clone https://github.com/你的用户名/ai-cs-bot.git
cd ai-cs-bot

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置环境变量
#    在项目根目录创建 .env 文件
```

`.env` 文件内容：

```env
LLM_API_KEY=sk-你的DashScope密钥
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
LLM_VISION_MODEL=qwen-vl-plus
```

### 启动服务

```bash
# 命令行启动
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# Windows 双击启动
start.bat
```

启动后在本机浏览器打开 http://127.0.0.1:8000 即可使用（仅限本机访问；远程部署需将 `--host` 改为 `0.0.0.0`）。

不想本地部署？可直接使用上方「在线体验」中的链接。

未配置 API Key 时自动进入模拟模式，工具调用和知识库检索正常工作，回复为预设模板。

## 前端设计

### 落地页

清新淡雅的浅绿色配色方案，六大区域：导航 / Hero / 核心能力 / 交互演示 / 全流程覆盖 / 技术架构。

### 客服调试模式

聊天窗口右上角的"客服模式"开关：
- **关闭（默认）**：普通用户只看到 AI 回复，不显示技术细节
- **开启**：客服可查看工具调用记录、参数、返回值、知识库命中详情

### 无障碍与性能

- 所有 SVG 图标 `aria-hidden`，键盘 `focus-visible` 样式
- `prefers-reduced-motion` 支持，前庭障碍用户可禁用动画
- 移动端汉堡菜单，触摸目标 >= 44px
- 滚动事件 `requestAnimationFrame` 节流 + `passive: true`
- `will-change` GPU 合成层优化，`backdrop-filter` 仅滚动时启用
- fetch 请求 60 秒超时 + 自动重试，`<noscript>` 降级提示
- 所有事件绑定使用 `addEventListener`，无内联 `onclick`

## 错误处理与稳定性

后端三层错误兜底，确保任何一层失败都不会导致页面崩溃：

| 层级 | 文件 | 错误处理 |
|---|---|---|
| LLM 调用 | `llm.py` | 30 秒超时 + try/except，失败返回友好提示 |
| 工具决策 | `agent.py` | function calling 失败时降级为规则引擎 |
| 路由层 | `routes.py` | `agent.run()` 包裹 try/except，返回结构化错误 |

前端两层防护：

| 防护 | 机制 |
|---|---|
| 60 秒超时 | `AbortController` 控制 fetch，超时自动中断 |
| 自动重试 | 超时后重试 1 次，重试时显示"正在重试..."提示 |
